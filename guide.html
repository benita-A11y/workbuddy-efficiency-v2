1文件下载与本地目录规范

这个平台由若干个文件组成，它们之间有固定的引用关系。只要目录结构摆对，用浏览器打开 index.html 就能直接用。下面是关键说明。

1.1 你需要的文件清单（共 6 个）

你提到的 4 个核心文件之外，还有 2 个让手机能「安装到桌面 + 离线可用」的 PWA 配置文件。少了它们，手机安装APP的功能会用不了，但网页本身仍能正常浏览。

文件类型作用必需？
index.html核心主页面结构必需
css/style.css核心全部样式、配色、响应式布局必需
js/storage.js核心数据存储层（自动保存、备份、回收站）必需
js/app.js核心应用逻辑（待办/复盘/记账渲染交互）必需
manifest.jsonPWA让手机能安装到桌面、定义图标和名称装APP必需
sw.jsPWAService Worker，离线缓存、断网可用装APP必需
6 个文件都要拿。少装 manifest.json 和 sw.js，网页能看，但装不到手机桌面、也做不到离线可用。后面用到的是完整 6 个文件。

1.2 正确的目录结构（必须保持这个层级）

关键点：index.html 里写死了去 css/ 文件夹找样式、去 js/ 文件夹找脚本。所以 CSS 必须放在 css 子文件夹、JS 必须放在 js 子文件夹，不能全堆在同一个目录里。

建议新建一个文件夹（例如 效率管理），把文件按下面结构摆放：

📁 效率管理/ ← 你新建的文件夹，名字随意 ├── index.html # 主页面 ├── manifest.json # PWA 配置 ├── sw.js # 离线缓存 ├── 📁 css/ │ └── style.css # 样式文件 └── 📁 js/ ├── storage.js # 数据存储 └── app.js # 应用逻辑
常见错误：把 6 个文件全放在同一层（没有 css、js 子文件夹），结果样式全丢、页面变成一堆没排版的文字。一定要建 css 和 js 两个子文件夹。

1.3 如何下载这 6 个文件

这些文件是我在本次对话中生成的，已保存在你的电脑项目目录里。你可以直接从那里拷贝：

文件所在路径：

C:\Users\thinkbook\WorkBuddy\2026-07-26-14-54-14\

用「文件资源管理器」打开这个路径，会看到 index.html、manifest.json、sw.js、css 文件夹、js 文件夹。把它们整个复制到你想存放的位置（如 D:\效率管理\）即可。

如果你想把文件存到别的地方（比如 U 盘），记得把 css 和 js 两个文件夹连同里面的文件一起拷走，保持上面的目录结构不变。

1.4 验证：双击 index.html 能正常打开吗？

找到 index.html，双击用浏览器打开
应该看到一个完整的页面：顶部有「待办 / 复盘 / 记账」三个标签，页面有配色、有内容。
检查样式是否正常
如果页面排版正常、有圆角卡片、有颜色，说明目录结构对了。如果变成一坨没样式的纯文字，回去检查 css 文件夹是否建对。
试着加一条任务
点击「+ 加任务到工作」，输入文字回车，任务出现在卡片里。关闭浏览器再打开，任务还在 → 说明数据存储正常。

到这一步，电脑端已经能用了。下面让手机也能访问。

2Windows 用 Python 启动局域网服务 + 防火墙放行

手机访问电脑上的网页，需要电脑先跑一个「网络服务」。用 Python 自带的功能最简单，一行命令搞定，不用装任何软件。

2.1 确认电脑装了 Python

按 Win+R，输入 cmd 回车，打开命令行，输入：

python --version

如果显示 Python 3.x.x，说明已装好，继续下一步。

如果提示「'python' 不是内部或外部命令」，说明没装。去 https://www.python.org/downloads/ 下载安装，安装时务必勾选 "Add Python to PATH"，装完重新打开 cmd 再试。

2.2 启动服务（一行命令）

在 cmd 里，先切到你的项目文件夹，再启动服务：

# 1. 切到项目文件夹（换成你自己的实际路径）
cd /d D:\效率管理

# 2. 启动服务，端口 8080，绑定 0.0.0.0 让局域网可访问
python -m http.server 8080 --bind 0.0.0.0

看到下面这行输出，就说明服务已经跑起来了：

Serving HTTP on 0.0.0.0 port 8080 (http://0.0.0.0:8080/) ...
--bind 0.0.0.0 这一段很关键，它表示「允许同一WiFi下的其他设备访问」。如果不加，手机可能连不上。
这个 cmd 窗口不要关，关了服务就停了。用完想停，按 Ctrl+C。

2.3 查电脑的局域网 IP 地址

手机要访问电脑，需要知道电脑在WiFi里的IP。重新开一个 cmd（或用同一个），输入：

ipconfig

在输出里找你正在用的网络：

  • 连 WiFi → 找「无线局域网适配器 WLAN」下面的「IPv4 地址」
  • 插网线 → 找「以太网适配器」下面的「IPv4 地址」

形如 192.168.1.105 或 192.168.0.23，把这个数字记下来。

无线局域网适配器 WLAN:
   ...
   IPv4 地址 . . . . . . . . . . . . : 192.168.1.105   ← 记住这个

2.4 先在本机自测

在电脑浏览器地址栏输入 http://localhost:8080，能正常打开平台就说明服务OK。

2.5 防火墙放行 8080 端口

Windows 防火墙默认会拦截外部设备（手机）的访问。需要放行 8080 端口，有两种方式。

方式 A：图形界面（推荐新手）

打开防火墙设置
按 Win，搜索「Windows Defender 防火墙」并打开 → 左侧点「高级设置」。
新建入站规则
左侧点「入站规则」→ 右侧点「新建规则…」。
选端口
选「端口」→ 下一步 → 选「TCP」→「特定本地端口」填 8080 → 下一步。
允许连接
选「允许连接」→ 下一步 → 三个网络类型（域/专用/公用）全勾（家用WiFi至少勾「专用」）→ 下一步。
命名并完成
名称填 效率管理8080（随意）→ 完成。

方式 B：命令行（一键，需管理员权限）

右键「开始菜单」→「Windows PowerShell（管理员）」或「终端（管理员）」，执行：

netsh advfirewall firewall add rule name="效率管理8080" dir=in action=allow protocol=TCP localport=8080

显示「确定。」即成功。这个规则只放行 8080，不影响其他端口，安全。

放行后，在手机浏览器输入 http://电脑IP:8080（如 http://192.168.1.105:8080）就能访问了。见第3部分。
如果手机打不开，按顺序排查：① 电脑服务是否还开着（cmd 窗口别关）；② 电脑和手机是否连的同一个WiFi；③ IP 是否输对（电脑端重新 ipconfig）；④ 防火墙规则是否建对；⑤ 路由器是否开了「AP隔离」（家用一般没开，公司网络可能有）。

3安卓 / iPhone 手机访问平台

前提：电脑服务已启动（第2部分）、防火墙已放行、电脑IP已知（如 192.168.1.105）。

3.1 安卓手机（Chrome / 自带浏览器）

连同一个 WiFi
手机「设置 → WLAN」连接和电脑同一个 WiFi。注意：手机用流量是访问不了的，必须 WiFi。
打开浏览器
打开 Chrome 或手机自带浏览器。
输入地址
地址栏输入：http://192.168.1.105:8080（换成你的实际IP），回车。
访问成功
看到「效率管理」页面，底部有「待办 / 复盘 / 记账 / 我的」四个标签，说明访问成功。可以正常使用了。

3.2 iPhone（必须用 Safari）

连同一个 WiFi
「设置 → 无线局域网」连接和电脑同一个 WiFi。
打开 Safari
这一步很关键：iPhone 上要用 Safari，不要用 Chrome（iPhone 版 Chrome 不支持安装PWA）。
输入地址
地址栏输入：192.168.1.105:8080（iPhone Safari 可以省略 http://），前往。
访问成功
看到完整页面即可。建议先点底部「记账」试试，能正常切换就说明OK。
建议把这个网址收藏到书签，下次直接点书签打开，不用每次手输IP。
记住地址格式：http:// 开头（不是 https），后面是电脑IP，冒号8080端口号。三部分缺一不可。如果路由器给电脑换了IP（重启路由器可能换），手机地址也要跟着改。

4把网页安装到手机桌面（PWA 离线可用）

这是最关键的一步。安装后，手机桌面会出现一个APP图标，点击直接全屏打开（没有浏览器地址栏），断网也能用已加载过的内容。这就是「类原生APP」体验。

前提：已通过第3部分在手机浏览器里成功打开平台至少一次。

4.1 安卓手机安装 Chrome

用 Chrome 打开平台
地址：http://电脑IP:8080。
触发安装
有两种情况：
① 自动提示：地址栏右侧可能出现「安装」图标或底部弹出「添加到主屏幕」横条，直接点。
② 手动安装：点右上角「⋮」菜单 → 找到「安装应用」或「添加到主屏幕」。
确认安装
弹出确认框，点「安装」。
完成
桌面出现「效率管理」图标（带 ◈ 标志）。点它打开，是全屏无地址栏的APP体验。
如果菜单里没有「安装应用」选项，确认 manifest.json 和 sw.js 这两个文件在项目目录里（见第1部分）。少了它们 Chrome 不显示安装选项。

4.2 iPhone 安装 Safari

用 Safari 打开平台
地址：电脑IP:8080。必须 Safari，iPhone 版 Chrome 装不了PWA。
点分享按钮
点 Safari 底部工具栏中间的「分享」图标（一个向上的方框带向上箭头 ↗）。
选「添加到主屏幕」
在弹出的分享菜单里，向下滚动找到「添加到主屏幕」（带 + 号的图标）。
命名并添加
可以改名字（默认「效率管理」），点右上角「添加」。
完成
回到桌面，会看到「效率管理」图标。点它打开，是全屏独立APP体验，顶部没有 Safari 地址栏。

4.3 安装后的效果

  • 全屏打开：没有浏览器地址栏和工具栏，像原生APP。
  • 独立任务：从最近任务列表里看是一个独立应用，不和浏览器混在一起。
  • 离线可用：第一次打开会把页面缓存下来，之后断网也能打开（Service Worker 在工作）。
    注意：离线时不能新增依赖网络的内容，但已加载的待办、记账数据是本地存储的，断网也能查看和编辑。
  • 启动快：直接点桌面图标，比每次打开浏览器输地址快得多。
更新内容怎么办：PWA 缓存有更新机制，联网打开时会自动检查更新。如果发现内容没刷新，关掉APP重开一次，或在浏览器里强制刷新一次原页面再重新安装。

5数据存储逻辑与备份方法

这部分关系到你辛辛苦苦记的任务、账单会不会丢，务必看懂。

5.1 数据存在哪里？

这个平台是纯前端应用，所有数据用浏览器的 localStorage 存储，存在你打开它的那个设备/浏览器里。具体存储位置：

项目说明
存储方式浏览器 localStorage（本地存储，不依赖网络）
存储键名efficiency_app_data（主数据）
efficiency_app_data_backup（自动备份）
efficiency_app_recycle_bin（回收站）
自动保存每次新增/修改/删除都立即写入，不用手动点保存
自动备份同时写一份备份，主数据损坏时自动从备份恢复
回收站删除的任务/账单进回收站，30天内可恢复
便利贴标注「仅本地」，只在当前设备保存
数据零丢失保障：实时自动保存 + 双重备份 + 回收站。正常使用下，关闭浏览器、重启电脑，数据都还在。

5.2 电脑和手机的数据互通吗？

这是最需要说清楚的一点。诚实说明：

当前实现下，电脑和手机的数据不自动互通。

原因：localStorage 是绑定到「具体设备的某个浏览器」的。你在电脑Chrome里记的任务，存在电脑Chrome；在手机Safari里记的任务，存在手机Safari。两者是各自独立的存储空间，不会自动同步。

页面顶部那个「同步状态」指示器（同步中/已同步），是模拟显示，并没有真正的云端服务器在后台做同步。需求文档里设想的「多端实时双向同步」需要部署后端数据库服务，当前的纯前端文件不包含这部分。

5.3 那怎么在多设备间迁移数据？

虽然没有自动云同步，但平台提供了手动导出/导入功能，可以在设备间迁移数据。流程：电脑端导出 JSON → 传到手机 → 手机端导入 JSON。

导出数据（电脑端）

方法一：顶部导出按钮
电脑端页面右上角有个「下载」图标按钮（向下箭头），点它，直接下载一个 .json 文件到电脑。
方法二：个人中心导出
（手机端也可用）点底部「我的」标签 → 找到「导出全部数据 (JSON)」按钮 → 点它下载文件。

导入数据（手机端 / 另一台设备）

进入个人中心
点底部「我的」标签。
点导入
找到「导入数据」按钮 → 选择之前导出的 .json 文件。
确认导入
提示「数据导入成功」后，刷新页面，所有任务/账单就出现在这台设备上了。
导入会覆盖：导入操作会用 JSON 文件里的数据替换当前设备的数据。建议导入前先在当前设备导出一份备份，以免覆盖丢失。两份合并需要手动整理。

5.4 日常备份建议

  • 定期导出：每周/每月在电脑端点一次导出，把 JSON 文件存到云盘（OneDrive/百度网盘）或U盘。
  • 大改动前先备份：要清空数据、换设备前，先导出一份。
  • 回收站兜底：误删任务/账单，30天内可在「我的 → 回收站」恢复。
  • 清空数据要谨慎：「我的」里有「清空所有数据」选项，会三次确认并提示先导出备份，清空后不可恢复。

5.5 想要真正的多端实时同步怎么办？

如果未来需要电脑和手机数据自动实时同步，需要额外部署一个后端服务（数据库 + 同步接口 + 用户登录）。这超出了当前 6 个前端文件的范围。目前的方案是「手动导出导入」做迁移，适合单设备为主、偶尔跨设备的个人使用场景。
